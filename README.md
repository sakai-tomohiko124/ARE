# ARE（アレ）— みんなで使えるチャットアプリ

HTML・CSS・JavaScript だけで作った静的サイトを **GitHub Pages** で公開し、データと認証は **Supabase** に置いています。
スマホ（縦向き推奨）・タブレット・パソコンの1つのファイル一式で動きます。**使い方は `help.html`（アプリの「その他」→「📖 操作方法」）を見てください。**

---

## 1. できること

| 分類 | 機能 |
|---|---|
| アカウント | 登録（ログインID・表示名・パスワード・電話かメールのどちらか必須）、ログイン、パスワードの目のボタン、復旧コードでの再設定 |
| チャット | 1対1／グループ、画像・動画・ファイル（PDF・Word・Excel・PowerPoint）、既読（オン・オフ可）、在席状況、編集、削除の申請（管理者が承認）、予約送信 |
| グループ | グループ名、注意事項、参考資料のリンク、アンケート、メンバーの追加・退出 |
| つながり | プロフィール編集（アイコン・ステータス・自己紹介）、投稿、フォロー、ユーザー検索、おすすめの非表示 |
| その他 | AIチャットボット（`chatbot.txt` を部分一致で検索）、天気予報、交通情報（外部サービスへのリンク）、1対1の通話（試験的） |
| データ | 会話履歴のZIP保存（端末へ）、アカウント削除の申請→承認→完全削除 |
| 管理者 | 全会話の閲覧、削除申請の承認、アカウントの作成・編集・削除、復旧コードの再発行、ログイン失敗の確認、Googleドライブへの毎日のバックアップ |

> 未対応：グループ通話、ライブ配信（無料で安定して動かす方法が見つかっていません）。通話は試験的で、回線によってはつながりません。

## 2. ファイル構成

```
index.html / index.js / index.css     起動画面
login.html / login.js / login.css     ログイン
register.html / register.js / .css    新規登録
recovery.html / recovery.js / .css    アカウント復旧
chat.html / chat.js                   メイン画面（チャット・投稿・管理者パネル）
extras.js                             ボット・天気・交通・通話
system.js                             Supabase との通信の共通部分
apikey.js                             Supabase の接続先（公開してよい値）
password-toggle.js                    目のボタンとパスワード条件の表示
chatbot.txt                           チャットボットの回答データ（自由に編集可）
help.html                             操作ガイド（スマホ・パソコン共通）
admin.html / admin.js                 旧式の管理画面（なくても動きます）
```

## 3. 公開のしかた（GitHub Pages）

1. 上のファイルを、リポジトリの**いちばん上の階層**に置く（フォルダを作らない）。
2. GitHub のリポジトリ → Settings → Pages → 公開するブランチ（`main`）と `/ (root)` を選ぶ。
3. 数分後、`https://（ユーザー名）.github.io/ARE/` で開けます。

## 4. Supabase の設定

1. **接続先**：`apikey.js` に、プロジェクトの URL と公開キー（`sb_publishable_…`）を書く。`service_role` キーは**絶対に書かない**。
2. **データベース**：テーブル・関数・保護ルール（RLS）は、Supabase の「Database → Migrations」に順番に記録されています。別のプロジェクトへ移すときは、その順に実行してください。
3. **Storage**（保存場所）：`chat-attachments`（非公開・50MB）、`post-images`（非公開・5MB）、`avatars`（公開・2MB）。
4. **Edge Functions**：`register-user`、`login-user`、`recover-account`、`admin-api`、`admin-delete-user`、`admin-manage-user`。
5. **自動送信（予約送信）**：拡張機能 `pg_cron` を有効にし、毎分 `deliver_due_scheduled_messages()` を実行するジョブを登録。
6. **Authentication**：メールの確認や新規登録の設定は、プロジェクトの方針に合わせて確認。パスワードの強さの設定にも、同じ条件（8文字以上・大文字・小文字・数字か記号）を入れておくと二重に守れます。
7. **管理者の登録**：SQL Editor で、管理者にする人の ID を `private.user_roles` に `role = 'admin'` で入れる。

## 5. Googleドライブへの毎日バックアップ

`gas-daily-backup.gs` と「GAS設定手順.md」を使います。前日分の会話とログイン失敗の記録が、ZIPで指定のフォルダに保存されます。**このファイル類は GitHub に置かないでください。**

## 6. セキュリティの考え方

**守りの本体はサーバー側です。** ブラウザの中のコードは、F12（開発者ツール）で誰でも見られ、書き換えられます。これは Web アプリの仕組みで、止める方法はありません（F12 を無効にする細工は、簡単に回避できる上、正しい利用者を困らせるだけなので入れていません）。そのため、「書き換えられても困らない」作りにしています。

| 守るもの | 守りかた |
|---|---|
| 他人の会話・データ | データベースの行ごとの保護（RLS）。自分の会話しか読めない |
| 管理者の操作 | サーバー側で管理者かどうかを毎回確認。画面を細工しても使えない |
| 重要な処理 | 検証つきの関数（RPC）や Edge Function だけが書き込む。直接の書き込みは禁止 |
| パスワード推測 | 5回失敗ごとに、回数と同じ分数だけロック（5回=5分、10回=10分…）。本人と管理者に通知 |
| 入力の悪用 | 長さ・形式の検査、リンクは https のみ、画面への表示は文字として扱う |
| 画面への不正な差し込み（XSS） | 各ページにコンテンツ・セキュリティ・ポリシー（CSP）を設定。外部のスクリプトは `cdn.jsdelivr.net`（バージョン固定）のみ許可 |
| 秘密の情報 | 公開キーだけをブラウザに置く。管理用の鍵はサーバー側のみ |
| 履歴・ログ | 管理者の操作は監査ログに記録。アカウント削除時は、本人の追跡ログも削除 |

**限界（正直な注意）：**
- GitHub Pages は、サーバー側の設定（セキュリティ用のヘッダー）を変えられません。画面の枠への埋め込み対策は、簡易的なものです。より強くするには、Cloudflare などを前に置く方法があります。
- 外部の `supabase-js` は、バージョンを固定していますが、ファイルの改ざん検知（SRI）は未設定です。ファイルを取得できる環境で、ハッシュを計算して追加してください。
- ログインの失敗回数は、「ログインID＋接続元」ごとに数えます。接続元を次々に変える攻撃には、Supabase 側の制限や Cloudflare の併用が有効です。
- 管理者は強い権限を持ちます。管理者アカウントのパスワードは特に厳重に。
- 顔写真の自動撮影は行いません（利用者のプライバシー、法令、悪用のおそれがあるため）。ログイン失敗は、日時・回数だけを記録します。

## 7. 運用メモ

- ログイン失敗の記録：管理者パネルの「セキュリティ」で確認。90日分を保持。
- 復旧コードの再発行・パスワード再設定：本人確認の方法を記録し、本人にマイページで通知されます。
- アカウント削除：申請 → 管理者が承認 → 完全削除。承認のたびに、追跡ログのZIP保存の有無を確認します。
- 個人情報：会話内容は管理者が閲覧でき、バックアップされる場合があることを、ログイン画面と登録画面に表示しています。法令・規約の確認は別途行ってください。

## 8. 動作確認のチェックリスト

- [ ] 新規登録（電話だけ／メールだけ／両方空はエラー）、弱いパスワードはエラー
- [ ] ログイン、目のボタン、パスワードを5回間違えるとロックされる
- [ ] 2つのブラウザで、1対1の送受信・既読・編集・削除申請→承認
- [ ] グループの作成、注意事項・リンク・アンケート
- [ ] 画像・動画・PDF・Word・Excel・PowerPoint の送信（日本語のファイル名も）
- [ ] 予約送信（1〜2分後）
- [ ] 投稿、フォロー、プロフィール編集
- [ ] ZIP保存（端末にダウンロードされる）
- [ ] 管理者パネル（管理者でだけ表示される）、アカウント作成・編集、削除申請→承認、ZIP保存の確認が出る
- [ ] スマホの縦画面、タブレット、パソコンで表示が崩れない

## 9. よくあるトラブル

| 症状 | 対処 |
|---|---|
| 真っ白・読み込めない | ブラウザの開発者ツールのコンソールを見る。CSP のエラーが出る場合は、`<meta http-equiv="Content-Security-Policy">` の許可先を確認 |
| 「権限がありません」 | RLS／関数の実行権限。新しい関数を作ったら、`service_role` や `authenticated` への実行権限を確認 |
| 予約送信が届かない | `pg_cron` のジョブが登録されているか確認 |
| 通話できない | 試験的な機能。回線によっては不可 |
